# exocad Dental CAD Scan Import and Design Errors: 3Shape Trios 3OXZ Import XML Error from Format Change Requiring STL or PLY Manual Import, Individual Dies Not Showing in Hide Show Box from Missing Separate Prep Files Requiring Scan Method Change, Unable to Load Scan Data on Duplicate Project from File Path Issue Requiring Manual Copy, Only Die Scan Imported from Missing Adjacent Tooth in Order Requiring Order Setup Fix, and Margin Line STL Export Not Available Requiring Web Share or Manual STL Save

exocad's intraoral scan import, die visibility, project duplication, scan data loading, and margin export produce errors from format incompatibilities, scan method differences, file path issues, order configuration, and export limitations. This guide covers the 5 most common exocad problems with diagnostic steps and community-verified fixes from Dental Lab Network.

## 1. 3Shape Trios 3OXZ Import XML Error from Format Change

### Symptom

Importing 3Shape Trios .3oxz files into exocad. Error message: "Document's Errors XML (18, 16). Entry characters chain was not in correct format." This never happened until the last Trios update. 3Shape support says it's an exocad problem. exocad support says it's a 3Shape problem.

### Root Cause

"Most likely, 3Shape changed something in their 3oxz format to make it incompatible, forcing Exo to play catch-up." 3Shape modified the .3oxz file format in a Trios update. The XML structure changed, making the files incompatible with exocad's importer. The .3oxz format is proprietary to 3Shape, and exocad needs to update their importer to handle the new format. The blame game between the two companies leaves users stuck.

### Fix

1. **Import STL or PLY files manually**:
   - "STL or PLY generated by Trios are still opened properly"
   - Export individual STL or PLY files from 3Shape Trios
   - Import the STL/PLY files into exocad manually
   - "If the margins are not marked, just create a new order and import it manually"

2. **Use the .3oxz import for convenience when it works**:
   - "When we import the .3oxz, it's quicker and easier: order ready, scan bodies automatic merged, bite scan"
   - When the import works, it saves time
   - When it breaks, fall back to manual STL import
   - Keep both workflows available

3. **Update exocad to latest version**:
   - "New exocad version 5675"
   - Check for exocad updates that may fix the 3OXZ import
   - The exocad team may release a patch for the new 3Shape format
   - Monitor exocad release notes for 3OXZ fixes

4. **Contact both support teams**:
   - Report the issue to both 3Shape and exocad
   - Provide the specific error message and XML position
   - Share a sample .3oxz file for testing
   - Request a timeline for the fix

5. **Use 3Shape's export to STL**:
   - In 3Shape Trios, export the scan as STL files
   - Export upper arch, lower arch, and prep separately
   - Import each STL into exocad
   - Mark margins manually in exocad

### Community Report

> "Anyone dealing with problems when trying to import 3Shape Trios .3oxz files to Exocad? Error: 'Document's Errors XML (18, 16). Entry characters chain was not in correct format.' Never had this issue till last Trios update. 3Shape support asked me to try Exocad support; Exocad support said is a 3Shape problem. Most likely, 3Shape changed something in their 3oxz format to make it incompatible. If the margins are not marked, just create a new order and import it manually."

## 2. Individual Dies Not Showing in Hide Show Box from Missing Separate Prep Files

### Symptom

In exocad's hide/show box, individual dies/preps are no longer listed. Previously could view only the preps as needed. Now the entire jaw disappears when trying to hide individual elements. Shift + middle mouse click hides the entire jaw instead of just the clicked object.

### Root Cause

"The problem cases don't have the individual prep file like the older cases do." The issue is caused by how the scans were imported. If preps were scanned individually (separate STL files per prep), they appear as separate items in the hide/show box. If the scan was imported as an intraoral scan (single arch file), individual preps can't be isolated. "In intraoral scan you cannot do that, same thing if you have scanned the model as solid/uncut."

### Fix

1. **Scan preps individually**:
   - "You probably have scanned each prep individual. This way, you can hide/view each prep"
   - "In intraoral scan you cannot do that, same thing if you have scanned the model as solid/uncut"
   - Scan each prep as a separate scan
   - Import each prep STL individually into exocad

2. **Complete margin line detection**:
   - "The additional sliders will show once the margin line detection is complete"
   - Run margin line detection on each prep
   - After detection, individual die sliders appear
   - This separates the die from the arch

3. **Check the case folder for individual prep files**:
   - "The problem cases don't have the individual prep file like the older cases do"
   - Open the case folder
   - Look for individual prep STL files
   - If missing, the scan method caused the issue

4. **Check Medit Link settings**:
   - "There must be a setting in Medit Link that is causing it to not be saved properly"
   - If using Medit Link for scanning
   - Check the export settings
   - Ensure individual prep files are exported

5. **Use keyboard shortcuts for visibility**:
   - "Try shift + middle mouse (clicking on the die/mesh you want invisible) to make an object invisible"
   - "Ctrl + shift + middle mouse button anywhere to bring it back"
   - "Both shortcuts stack meaning you can make multiple objects disappear"
   - This works when individual items are separate meshes

6. **Reimport with correct settings**:
   - Delete the current import
   - Reimport with individual prep files
   - Ensure each prep is a separate STL
   - The hide/show box will show individual items

### Community Report

> "In the hide/show box the individual dies/preps are no longer there. I used to have the option to view only the preps as needed. The problem cases don't have the individual prep file like the older cases do. In intraoral scan you cannot do that, same thing if you have scanned the model as solid/uncut. The additional sliders will show once the margin line detection is complete. Try shift + middle mouse to make an object invisible."

## 3. Unable to Load Scan Data on Duplicate Project

### Symptom

Creating a duplicate project in exocad. When opening the duplicate for design, error: "Unable to Load Scan Data." The original project works fine. The duplicate can't find the scan data files.

### Root Cause

When exocad duplicates a project, it copies the project database but may not correctly update the file paths for the scan data. The duplicate project's database references the original project's scan data paths, which may not be valid in the duplicated folder structure. The scan data files may not be copied to the duplicate project folder.

### Fix

1. **Check the duplicate project folder**:
   - Open the duplicate project folder
   - Verify scan data files (STL, PLY) are present
   - If missing, manually copy from the original project
   - Ensure file names match the database references

2. **Copy scan data manually**:
   - Copy the scan data files from the original project folder
   - Paste them into the duplicate project folder
   - Ensure the file names match exactly
   - Reopen the duplicate project

3. **Check file paths in the database**:
   - The exocad database stores file paths
   - The duplicate may reference original paths
   - Use the exocad DB healer tool to fix paths
   - Or manually edit the database entries

4. **Use exocad's duplicate function correctly**:
   - Use File > Duplicate Project within exocad
   - Don't manually copy the folder
   - The built-in function should handle file paths
   - If it fails, report to exocad support

5. **Create a new project and import scans**:
   - If duplication doesn't work
   - Create a new project from scratch
   - Import the scan data from the original project
   - This is more work but guarantees correct file paths

6. **Use the DentalWatcher X tool**:
   - "Sharing a Utility: ExoCAD db healer - Tidying Up Exocad Project Folder Names"
   - Community tools can help fix project database issues
   - Check the Dental Lab Network for utility tools
   - These can repair file path references

### Community Report

## 4. Only Die Scan Imported from Missing Adjacent Tooth in Order

### Symptom

Set up a new scanner. Everything scans great — upper, lower, prep all registered separately in scan app. When exocad opens, it only opens the die scan and opposing. The full arch is missing. Orientation is off. Need to import an extra jaw scan for every case.

### Root Cause

"It was as simple as adding an adjacent tooth to the order." The exocad order setup was missing the "adjacent tooth" designation. Without an adjacent tooth in the order, exocad doesn't expect or import the full arch scan — it only imports the die scan and opposing arch. Adding an adjacent tooth to the order tells exocad to expect and import the full arch.

### Fix

1. **Add adjacent tooth to the order**:
   - "It was as simple as adding an adjacent tooth to the order"
   - In the exocad DentalDB (order setup)
   - Add an adjacent tooth to the restoration order
   - This tells exocad to import the full arch scan

2. **Check order setup in DentalDB**:
   - Verify the order includes all necessary components:
   - Restoration tooth (prep)
   - Adjacent tooth (full arch)
   - Opposing arch
   - Bite registration (if applicable)

3. **Verify scan app export settings**:
   - "Everything is scanning great, upper/lower/prep all registered separately in scanapp"
   - Check the scan app (Medit Link, 3Shape, etc.)
   - Ensure all scans are exported
   - Verify the export format matches exocad expectations

4. **Check orientation settings**:
   - "The orientation is off"
   - After adding the adjacent tooth, check orientation
   - Verify upper and lower arches are correctly oriented
   - Use exocad's orientation tools if needed

5. **Update exocad to a newer version**:
   - "It is an older version of exocad that I was using"
   - Newer versions may handle import more intuitively
   - "Must be very old software, haven't seen this since like Matera or earlier"
   - Consider upgrading to the latest exocad version

6. **Use automatic import for intraoral scanners**:
   - "If you set up automatic import for exocad"
   - "It will also bring in pictures from the scanner and NIFR scans"
   - Configure auto-import for your scanner
   - This ensures all scan data is imported correctly

### Community Report

It was as simple as adding an adjacent tooth to the order. Little things like this make me hate exocad. It's powerful software, but not intuitive or user friendly like 3shape. It is an older version of exocad that I was using."

## 5. Margin Line STL Export Not Available

### Symptom

Need to generate a margin-marked STL from exocad to share with doctors for margin approval. When receiving iTero scans with marked margins, iTero generates a separate STL showing the margin marking. Need to do the same from exocad — generate a margin-marked STL that can be shared via web share.

### Root Cause

"Doesn't look like it unless I'm missing something obvious. Looks like it generates scaninfo files." exocad doesn't have a direct "export margin-marked STL" function. The margin line is stored internally and used for design, but there's no one-click export to create a STL with visible margin markings. exocad keeps temporary STLs of margins but they overlap with the model and are hard to distinguish in online viewers.

### Fix

1. **Use web share of crown bottoms and prep arch**:
   - "The closest I've come up with is just generating a web share of the crown bottoms and the prep arch"
   - "But it's not that clear where the actual margins are marked doing it that way"
   - Use exocad's web share feature
   - Share the prep arch with the doctor

2. **Save temporary margin STLs**:
   - "Exocad keeps temporary STL's of the margins that are essentially the whole prep face from margin to margin"
   - "You can right click and save these as stls if you'd like"
   - "But the shape of them isn't super helpful for your case"
   - "In the online viewer they overlap with the actual model"

3. **Use a custom Blender script**:
   - "I've had success with a little app I made that uses Blender scripting"
   - "I drag and drop a simple xyz or pts and it outputs a STL of the margin as a thin 3d spline"
   - Export the margin line as xyz or pts coordinates
   - Use Blender to convert to a visible STL

4. **Check for xyz or pts margin line file**:
   - "Does exocad give you a xyz or pts margin line file like 3shape?"
   - "Just a list of coordinates as a text file?"
   - Look in the exocad project folder for coordinate files
   - These may contain the margin line points

5. **Use iTero automatic import**:
   - "With Itero specifically you can get a lot more info if you set up the automatic import for exocad"
   - "It will also bring in pictures from the scanner"
   - "Nice info, can even mark margins directly on the pictures instead of the scan"
   - "But all that info is unavailable if you don't auto import them"

6. **Share screenshots of margin line**:
   - Take screenshots of the margin line in exocad
   - Annotate the screenshots
   - Share with the doctor for approval
   - This is low-tech but effective

### Community Report

> "Is there any way in exocad to generate a margin marked STL, so that I can share that and the prep arch via the web share to the doctor, and then the dr can approve the margin? The closest I've come up with is just generating a web share of the crown bottoms and the prep arch. Exocad keeps temporary STL's of the margins. You can right click and save these as stls. With Itero specifically you can get a lot more info if you set up the automatic import for exocad."

## 6. Additional exocad Issues

### exocad Not Intuitive or User Friendly

**Issue**: "It's powerful software, but not intuitive or user friendly like 3shape."
**Fix**: "It doesn't hand-hold." Invest in training. Use CAM Wizard tutorials. Join Dental Lab Network for community support. Consider 3Shape or Dentbird as alternatives if UX is critical.

### High Upgrade Cost

**Issue**: "I just asked Imagine about it last week, it's $6000."
**Fix**: Evaluate if the upgrade features are worth the cost. Compare with alternative software (3Shape, Dentbird, B4D). Consider pay-per-crown cloud services like Dentbird as an alternative to perpetual licensing.

### Scan App Integration Issues

**Issue**: Different scan apps (Medit Link, 3Shape, iTero) have different integration levels with exocad.
**Fix**: Use automatic import where available. Check scan app export settings. Verify file naming conventions. Test the full workflow before production use.

### Database Management

**Issue**: exocad project databases can become corrupted or have inconsistent entries.
**Fix**: "Preserve Project DB health: Check Consistency, Clean Database." Use the exocad DB healer tool. Regularly back up project databases. Use the DentalWatcher X utility for file organization.

## Best Practices

1. **Import STL or PLY when 3OXZ format breaks** — 3Shape format changes cause import failures
2. **Scan preps individually for hide/show isolation** — intraoral scans can't isolate individual preps
3. **Complete margin line detection to enable die sliders** — separates die from arch in hide/show
4. **Use shift + middle mouse for quick visibility toggle** — stacks for multiple objects
5. **Copy scan data manually if duplicate project fails** — check for missing STL files
6. **Add adjacent tooth to order for full arch import** — without it, only die scan imports
7. **Use automatic import for iTero scans** — brings in pictures and NIFR scans
8. **Use web share for doctor margin approval** — share crown bottoms and prep arch
9. **Save temporary margin STLs for sharing** — right-click and save from exocad
10. **Invest in training — exocad is not intuitive** — use CAM Wizard and community resources
